# One-box resident-engine transition

Scope: Gemma-4 31B text-only greedy inference, TP16 ↔ two TP8 engines, four persistent controllers. Optional multimodal, speculative decoding, connectors and prefix caching are not part of this experiment. The starting checkpoint loader is the normal loader from restore/sharded-snapshot (cc0f44f); no checkpoint read is permitted after the first load.

The normal loader initially failed inside the explicit distributed runtime because common/utils.py cpu_mesh() selected global CPU device 0 on every process. The prototype overrides this load-time helper to process-local CPU devices, restoring the original helper immediately after loading. Run raysubmit_2jYM52YJbHbHa6jD then loaded the real model on all four hosts (262.459–264.821 s) before an executor-interface issue; this is initial-load evidence, not a reconfiguration measurement.

Launcher inputs are uploaded as a temporary working-directory JSON, not large environment variables. The earlier 147 KB runtime_env prevented Ray job-supervisor worker registration (startup_failure.json, raysubmit_jbxYVqFKCLAvSaWB). Engine cores attach by JSON-hashable named actor identifiers because vLLM hashes additional_config with json.dumps; the executor resolves those names once at initialization. The synchronous prototype fulfills vLLM's non_block execute_model contract with a completed Future.

Keep the four Ray actors/processes, one distributed JAX/PJRT runtime, and resident parameter array handles. All controllers rendezvous for transitions; only controllers belonging to an engine execute its inference RPCs. Explicit device lists select the submeshes (the normal worker's device_indexes path selects only local devices and its default chooses the first N global devices).

Retire admission and drain all requests and async sampling. Drop the LLMEngine/EngineCore scheduler, structured-output manager, KVCacheConfig/block allocator and executor bindings. Delete runner KV arrays, InputBatch, device metadata buffer, attention/cache managers, sampling state, and mesh-capturing compiled functions. Keep parameter state outside the runner before releasing it. Construct a fresh runner and abstract NNX Gemma graph for each destination mesh, derive destination partition specs from that graph, and transfer array leaves with JAX device_put without host materialization. Rebuild model graphdef/state metadata and get_flax_model closures by temporarily replacing only _get_nnx_model during the load-time closure construction; the replacement returns the already resident abstract graph, never its load_weights method. Then recompute KV spec, allocate KV and compile/warm. Record all per-controller wall-clock phases and first token.

Merged gate_up and fused QKV weights require TP-dependent packing conversion, not only placement: each TP shard stores concatenated per-projection slices. The transition unpacks source TP16 interleaving and repacks TP8 (and vice versa) in JAX on TPU; unequal Q/K/V sizes and optional bias follow module output_sizes. Fresh graph metadata is retained. The source and destination arrays remain device-resident throughout.

A dedicated prototype Executor attaches to actor handles provided in additional_config. It never starts actors, calls init_device, reloads model weights, or shuts down their runtime. Its collective RPC broadcasts scheduler outputs to participating hosts and returns rank-zero sampling output. Initial workers are created once outside the executor. New LLMEngine cores use the existing vLLM constructor and scheduler/cache initialization. Executor shutdown merely detaches; actor teardown belongs to the outer driver finally block.

TP16→TP8 uses one global 16-device replica mesh whose model axis has size 8, then metadata-only submesh handles alias its local device shards. TP8→TP16 reshares the retained 16-device global replica handle back to the TP16 mesh. This avoids a pinned JAX 0.10.2 restriction: direct device_put cannot simultaneously change the source/destination device sets and shard indices (ICIBench real-model run raysubmit_9X6TMp5AiWsRpjCS). Both copies remain unchanged under inference-only serving. Destination NNX metadata is never copied from source, since KV head partitioning can differ.

Reconfiguration C starts before the drained engine is retired and ends at the first output token from every new engine. Initial loading and the correctness/throughput batches are outside C. Two round trips distinguish first-switch and repeated-switch warm-up; the compilation-cache directory persists through the actor lifetime. A synchronous Ray RPC executor is deliberately simple but can add decode overhead; throughput comparison must include it, not infer equivalence from parameter correctness.

The first-token C endpoint differs from the historical full-slice deployment/first-dispatch/ramp endpoint; comparisons are explicitly labeled rather than treated as identical experiments. A unique per-run compilation-cache directory makes the first in-runtime TP8 compile cold; the second switch reuses that same directory.

Production requires transactional failure recovery, request fencing/generations, bounded-memory layerwise transfer qualification and a persistent-worker executor in tpu-inference. Gateway integration needs withdrawn old registrations and atomic new capacity publication. Full 32-chip execution needs eight controllers, both boxes transitioning in lockstep and shared-runtime failure handling. M needs retaining one TP16 box while only the other box transitions, with disjoint-process collectives and routing generation updates. None is qualified by the one-box prototype.

The prototype's {0,1}/{2,3} grouping follows native controller order: its TP8 meshes cover horizontal 4x2 chip rectangles, unlike the normal S layout's vertical 2x4 rectangles. The standalone throughput control uses the same first two physical hosts and 4x2 geometry; greedy reference tokens still come from normal S. The first control attempt omitted :8471 in TPU_PROCESS_ADDRESSES and failed before loading (run_standalone8.json, raysubmit_4EFJc9HXknsq98mf); corrected control also resets both host/process bounds and topology. For M, independent work on the unchanged box during a global reshard is not yet safe: ICIBench's measured native slice/neighbor-compute failure requires additional collective-order qualification, not an assumption of isolation.

## Compilation-cache qualification and opt-in workaround

The unpatched four-controller runtime does not warm TP8-B's persistent cache: JAX 0.10.2 compiler.py:802-805 permits writes only from global process 0, outside B's participating {2,3}. Run raysubmit_rE7JacZHsNEpThfB measured A warm-up 170.409 -> 32.732 s and B 159.984 -> 162.480 s, with unchanged 116 KV blocks on every controller. This supports the source-derived explanation; it is not a cache-hit counter measurement. Device assignments are retained in TPU cache keys (jax/_src/cache_key.py:129,327), unlike the GPU path.

An explicit --submesh-cache-writer flag enables a prototype-only in-process wrapper from hetero/ici_resident.py. It brackets compilation with a context-local participating-process set, selects its lowest rank, and invokes the original _cache_write body with a private copied globals dictionary whose guard sees process 0. It never mutates JAX's distributed global state, installed packages, or serving-step logic. Callback/duration/error/serialization policies remain native. Other controllers skip that key; A/B's different TPU device assignments separate their cache keys. Cache-key/eligible-writer events are archived to check that no key acquires competing writers. The wrapper refuses JAX versions other than 0.10.2; upstream should replace the global-rank predicate with a computation's participating leader instead.

Warm-up must start after both LLMEngine constructors finish: the constructor's reset_mm_cache RPC otherwise queues behind the first engine's warm-up and serializes construction. The driver prepares both KV/core instances, starts warm-up on all four controllers, then waits for both groups. Patched and unpatched arms use different run IDs/cache directories and remain separate evidence.

Reproduce from this worktree (inventory /tmp/hetero-inventory-only.json and Ray port-forward already prepared):

- Unpatched round trips: flock /tmp/hetero-cluster.lock scripts/ici_engine_sequence.sh --run-id inplace-unpatched-UNIQUE --output results/ici/InPlaceEngine/run_parallel_warmup.json
- Standalone TP8 control: flock /tmp/hetero-cluster.lock scripts/ici_engine_sequence.sh --standalone-tp8 --run-id inplace-control-UNIQUE --output results/ici/InPlaceEngine/run_standalone8_corrected.json
- Patched round trips: flock /tmp/hetero-cluster.lock scripts/ici_engine_sequence.sh --submesh-cache-writer --run-id inplace-patched-UNIQUE --output results/ici/InPlaceEngine/run_mesh_cache_writer.json
- Summarize an arm: .venv/bin/python scripts/ici_engine_analyze.py results/ici/InPlaceEngine/run_mesh_cache_writer.json --standalone results/ici/InPlaceEngine/run_standalone8_corrected.json
- Local invariants: JAX_PLATFORMS=cpu XLA_FLAGS=--xla_force_host_platform_device_count=16 uv run --no-project --isolated --with flax==0.12.4 --with jax==0.10.2 python -m unittest tests.test_ici_resident -v

Use a fresh run ID for a cold-cache arm. Keep the flock blocking with no outer timeout and use the sequence's RCM teardown trap. No weights are staged in /dev/shm by this prototype. Decode sanity rates are whole fixed-batch rates and post-first-token rates (including prefill tail), not isolated steady-state kernel rates.


## Measured round-trip outcome

Unpatched explicit parallel warm-up (raysubmit_eZ37RTqNQBVq2r5T): TP16 to two TP8 costs 236.951 s cold / 229.495 s second switch; return TP16 costs 76.466 / 75.855 s. Patched participating-leader writer (raysubmit_6Kx3zaVPJJwS7UvW): 241.936 / 100.624 s to two TP8, 77.448 / 76.778 s returning. All seven batches per arm, 32 W0 prompts each, are token-identical to normal H/S reference engines. Every controller retained its PID and exactly one initial JAX initialization/checkpoint-load entry.

The cache patch changes B cold/second warm-up from 158.952 / 163.734 s to 171.072 / 33.444 s; A is 174.794 / 33.354 s in the patched arm. There are 451 eligible TPU cache keys and no competing writer ranks for any key. Warm patched forward transition has per-controller drain 0.0017-0.0019 s, KV/runner free 1.44-1.47 s, repacking 0.615-0.616 s, abstract graph 14.97-15.41 s, device-put/handle reshard 3.43-3.87 s, closure rebuild 0.40-0.81 s, KV allocation 12.15-12.20 s per engine, and warm-up 33.35-33.44 s. End-to-end C includes head/frontend/executor binding and sequential core/KV setup not isolated in those worker durations.

Warm 100.624 s is arithmetically 120.776-127.976 s below restore C 221.4-228.6 s and 318.376 s below full redeploy 419 s. These are differently scoped endpoint comparisons, not a measured 32-chip production result. Cold in-place cost remains 241.936 s and does not beat warm-cache restore. Exact values/provenance are in cost_comparison.json and per-controller transition/cache/lifetime JSON.

Corrected two-controller standalone control raysubmit_dSDKwhfgqiejg4qN returned the same 2035 greedy output tokens for the 32 prompts. Post-first-token batch rate is 374.694 tokens/s; in-runtime TP8-A/B are 354.459 / 361.516 after the cold switch and 370.694 / 373.482 after the second switch. Repeated-switch slowdown is 1.067% / 0.323%; cold-switch batches are 5.401% / 3.517% slower. Both resident engines run simultaneously, whereas the control runs one engine. This small fixed-batch result does not qualify sustained full-slice rates or the production Ray-DAG executor. throughput_check.json records the exact rate definition, matched prompt/sampling contract and limitation.

Final read-only Ray state API verification observed every ici-inplace-* actor DEAD and every ici-in-place-inplace-* placement group REMOVED (cleanup_check.json). The prototype leaves no resident actors or placement groups. Raw experiment evidence retains the full diagnostic catalogue/cache histories; transition summaries omit those duplicate diagnostic payloads and keep every per-controller phase timing.
